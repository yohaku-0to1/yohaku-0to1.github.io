Remotionとは

Remotionは、「ReactのコンポーネントをMP4動画として書き出す」ためのフレームワークです。 従来の動画編集ソフト（Premiere ProやAfter Effects）とは異なり、すべてをコードで制御します。

なぜRemotionなのか？
  • プログラマブル: APIデータを使って1000本の動画を自動生成する、といったことが可能です。
  • Web技術の活用: CSS Flexbox/Grid、SVG、Canvas、WebGLなど、Webの表現力をそのまま動画に使えます。
  • バージョン管理: 動画プロジェクトをGitで管理できます。

環境構築

Node.js (v18以上 LTS推奨) が必要です。
FFmpegは、Remotionが動画レンダリング・バンドル処理に必要なものを内部で管理するため、基本的には手動インストール不要です。

FFmpegの自動ダウンロード:
Remotionの初回起動時に、必要なFFmpegが自動的にダウンロードされます。
ただし、CI/CD環境（Docker、GitHub Actions、Vercel、Renderなど）やプロキシ環境では、自動ダウンロードが失敗する場合があります。 その際は手動でFFmpegをインストールする必要があります。詳細は公式ドキュメントを参照してください。
Apple Siliconユーザーへ:
M1/M2/M3 Mac では、Homebrew経由でFFmpegをインストールしておくとトラブルが少なくなります。
brew install ffmpeg
# 新規プロジェクトの作成
npx create-video@latest

テンプレートは Hello World (TypeScript) を推奨します。最もシンプルで構造を理解しやすいためです。

学習チェックリスト - まずはここまでやればOK！
  • ☑ Node.js 18以上をインストール
  • ☑ npx create-video@latest でプロジェクト作成
  • ☑ npm run dev でStudioを起動してプレビュー
  • ☑ useCurrentFrame() と interpolate() でシンプルなフェードインを作成
  • ☑ Sequence で複数クリップを配置

最小の動作コンポーネント例

Remotionの最小構成を理解するため、完全に動作するシンプルな例を示します。 以下は1つのプロジェクトの基本構造です。

src/Root.tsx（動画の設計図）

📝 TypeScript

import { Composition } from 'remotion';
import { MyVideo } from './MyVideo';

export const RemotionRoot = () => {
  return (
    <Composition
      id="MyVideo"
      component={MyVideo}
      durationInFrames={150}
      fps={30}
      width={1920}
      height={1080}
    />
  );
};

src/MyVideo.tsx（実際の映像）

📝 TypeScript

import { useCurrentFrame, interpolate } from 'remotion';

export const MyVideo = () => {
  const frame = useCurrentFrame();
  const opacity = interpolate(frame, [0, 30], [0, 1]);

  return (
    <div style={{ opacity, fontSize: 80 }}>
      Hello Remotion!
    </div>
  );
};

このコードで、30フレーム（1秒）かけてフェードインするテキストが完成します。
useCurrentFrame() と useVideoConfig() から取得できる fps などの値は、 上記の Composition で定義した設定から自動的に提供されます。

複数のCompositionを管理:
実際のプロジェクトでは、複数の Composition を同時に管理できます。
例えば、本編・サムネイル・TikTok版・YouTube版などを1つのプロジェクトで作成可能です。

📝 TypeScript

<Composition id="Main" ... />
<Composition id="Thumbnail" ... />
<Composition id="TikTok" ... />

開発ワークフロー

Remotionでの開発は、ブラウザ上のプレビューツール「Remotion Studio」を中心に行います。

💻 Shell

npm run dev

このコマンドを実行すると、ローカルサーバーが立ち上がり、ブラウザで動画をプレビューできます。 コードを保存すると即座に反映される「Fast Refresh」機能があるため、効率的に試行錯誤できます。

使い分けガイド

やりたいこと 使うコマンド／ツール 出力物
動きを確認したい npm run dev ブラウザプレビュー（Remotion Studio）
動画ファイル（MP4）を書き出したい npx remotion render MP4ファイル
Webで公開したい npm run build 静的Webページ（WebBundle）
Studio と Render の違い:
  • Studio (dev): ブラウザでリアルタイム描画。開発・デバッグ用。
  • Render: 1フレームずつ正確に再描画してMP4化。フレームの順番は保証されない（並列処理のため）。
これは「ReactのSSR（サーバーサイドレンダリング）」に似た世界です。 だからこそ useEffect による状態管理ではなく、useCurrentFrame() ベースの純粋関数的なコンポーネント設計が必須になります。

レンダリングの仕組み (The Frame Loop)

Remotionの核心は「現在のフレーム数 (frame) に基づいてUIを描画する」ことです。 動画再生中、Remotionは毎秒30回（30fpsの場合）、コンポーネントを再レンダリングし、その都度 useCurrentFrame() の値を更新します。

📝 TypeScript / JavaScript

const frame = useCurrentFrame();
// frame: 0 -> 1 -> 2 -> 3 ...

この frame の値を使って、不透明度や位置などのスタイルを計算します。これがアニメーションの原理です。

Reactライフサイクルと動画

useEffect の注意点:
useEffect をアニメーション状態（動画の内容）に使うのはNGです。
ただし、delayRender のような「完了通知用途」では問題ありません。
  • ❌ NG: useEffect でカウントアップしてアニメーション
  • ✅ OK: useEffect + delayRender でデータ読み込み完了を通知
理由: Studio（プレビュー）では動きますが、render（MP4書き出し）時に破綻します。

したがって、「時間の経過とともに状態が変化する」ロジック（例: setInterval や useEffect でのカウントアップ）は使ってはいけません。 常に useCurrentFrame() から一意に定まる「純粋関数」のようなコンポーネントを作る必要があります。

❌ ダメな例：フレーム順が保証されない

📝 TypeScript / JavaScript

useEffect(() => {
  setCount(c => c + 1); // レンダリングのたびに結果が変わる！
}, []);
✅ 正しい例：frameに依存

📝 TypeScript / JavaScript

const frame = useCurrentFrame();
const count = Math.floor(frame / 10); // 常に同じ結果

Propsとパラメータ

動画の内容を動的に変えるために、コンポーネントに props を渡すことができます。 ルートの Composition でデフォルト値を設定し、レンダリング時に上書きすることが可能です。

<Composition
  id="MyVideo"
  component={MyVideo}
  defaultProps={{ title: "Hello" }}
/>

Sequence と Series（タイムライン制御）

動画編集のタイムラインのように、クリップを配置するためのコンポーネントです。

Sequence

絶対的な時間指定、または相対的な配置を行います。 from で開始フレーム、durationInFrames で長さを指定します。

ネスト時の挙動:
Sequenceを入れ子にした場合、子のSequenceの from は親のSequenceの開始位置が基準になります。
<Sequence from={0} durationInFrames={30}>
  <Title />
</Sequence>
<Sequence from={30}> // 30フレーム目から開始
  <Subtitle />
</Sequence>

Series

「前のクリップが終わったら次」という風に、自動的に順番に並べてくれます。計算の手間が省けます。

<Series>
  <Series.Sequence durationInFrames={60}>
    <Scene1 />
  </Series.Sequence>
  <Series.Sequence durationInFrames={90}>
    <Scene2 /> // 自動的に60フレーム目から開始
  </Series.Sequence>
</Series>

AbsoluteFillとレイアウト

Remotionには AbsoluteFill という便利なコンポーネントがあります。 これは以下のスタイルが適用された div です。

position: absolute;
top: 0; left: 0; right: 0; bottom: 0;
display: flex;
flex-direction: column;

動画の各レイヤーは基本的に画面いっぱいに広がるべきなので、コンポーネントのルート要素として多用します。

画像・フォントの読み込み

画像や動画ファイルは public/ フォルダに置き、staticFile() 関数を使ってパスを解決するのがベストプラクティスです。

import { staticFile } from 'remotion';
<Img src={staticFile("logo.png")} />

フォントは @remotion/google-fonts を使うと非常に簡単に導入できます。

Interpolate (補間)

数値をマッピングする関数です。アニメーションの基本中の基本です。

const opacity = interpolate(
  frame,
  [0, 20], // 入力: 0フレームから20フレームの間
  [0, 1], // 出力: 0(透明)から1(不透明)へ
  { extrapolateRight: 'clamp' } // 20フレーム以降は1を維持
);

Spring (物理挙動)

なぜspringが必要か？

interpolate だけでもアニメーションは作れますが、線形的な動きは「機械的」に見えることがあります。 spring を使うと、バネのような物理挙動（加速・減速・オーバーシュート）が自動生成され、 見た目に自然でリッチな動きになります。

springが役立つ状況:
  • ロゴやテキストの登場に「弾む感じ」が欲しい時
  • UI要素のアニメーションを心地よくする
  • 線形の interpolate だと動きが平板に感じる場合
注意: Remotionの spring() は独自の物理演算APIです。react-spring ライブラリとは別物です。

📝 TypeScript / JavaScript

const scale = spring({
  frame,
  fps,
  config: {
    damping: 20, // 低いほど跳ねる（推奨: 10-30）
    stiffness: 200, // 高いほど速い（推奨: 100-300）
    mass: 1 // 質量（通常は1で OK）
  }
});

damping だけでなく stiffness も調整することで、より自然な動きを実現できます。 公式推奨値は damping: 20, stiffness: 200 です。

Spring の動きイメージ（数値例）:
scale を 0 → 1 にアニメーションさせた場合の推移例：
  • frame: 0 → scale: 0.00
  • frame: 10 → scale: 1.12（オーバーシュート）
  • frame: 20 → scale: 0.96（反動）
  • frame: 40 → scale: 1.00（収束）
このように「跳ねて安定する」物理挙動が自動生成されます。

非同期データ読み込み (delayRender)

なぜdelayRenderが必要か？

Remotionはフレームごとにコンポーネントをレンダリングしますが、 APIからデータを取得したり、重いフォントを読み込む場合、データがそろう前にレンダリングが始まってしまうと、映像が欠けたりフリッカーしたりします。

delayRender と continueRender を使うことで、「データが準備できるまでレンダリングを待機」させることができます。

使用状況:
  • APIからデータをfetchして動画に反映する場合
  • カスタムフォントの読み込みを待つ必要がある場合
  • 画像や動画のプリロードを確実にする場合
const [handle] = useState(() => delayRender());

useEffect(() => {
  fetchData().then(data => {
    setData(data);
    continueRender(handle); // 準備完了を通知
  });
}, []);

乱数生成 (Randomness)

なぜMath.random()ではダメなのか？

Math.random() は禁止！
Remotionのレンダリングは、複数のブラウザインスタンスで並列にフレームを描画します。 Math.random() を使うと、同じフレームでもレンダリングのたびに異なる値が生成され、映像がフリッカーしたり、プレビューと書き出しで結果が変わる原因になります。

解決策として、Remotionの random() 関数を使い、シード値を渡します。 同じシード値からは常に同じ乱数が生成されるため（決定的乱数）、レンダリングのタイミングに関係なく一貫した結果を得られます。

randomSeed() とは？
randomSeed() は決定的な乱数ストリームを生成するシード値を返す関数です。
シード値は数値でも文字列でもOKです。同じシードからは常に同じ乱数系列が生成されます。
複数の乱数値を使いたい場合は、数値を加算したり文字列で区別します。
Compositionレベルでの乱数管理:
Composition の defaultProps で randomSeed を指定すると、 映像全体を統一された乱数系列で制御できます。これにより、書き出しごとに結果が変わることを防げます。
import { random, randomSeed } from 'remotion';

// シンプルな使い方
const x = random("my-seed") * 100;

// 複数の乱数値を管理する場合
const seed = randomSeed(1); // 決定的な数値が返る
const x = random(seed) * 100;
const y = random(seed + "b") * 50; // 文字列で区別

オーディオ可視化

音楽に合わせて動くビジュアライザーを作るには、@remotion/media-utils の useAudioData を使います。 オーディオファイルの波形データを取得し、フレームごとの音量を数値化できます。

import { useAudioData, visualizeAudio } from '@remotion/media-utils';
import { staticFile } from 'remotion';

const audioData = useAudioData(staticFile("music.mp3"));

// 読み込み中はnullになるためガード
if (!audioData) return null;

const visualization = visualizeAudio({
  fps,
  frame,
  audioData,
  numberOfSamples: 16
});
ヒント:
visualizeAudio() 関数を使うと、特定の周波数帯域の音量を取り出すことも可能です。 低音に合わせてベースを揺らす、といった表現ができます。

実用例: 一瞬で「音楽に反応する円柱グラフ」や「PVのビジュアライザー」などが作れます。

動画の書き出し

Remotionで作った動画をMP4ファイルとして書き出すには、remotion render コマンドを使います。

基本的な使い方

多くの場合、以下のシンプルな構文で書き出せます：

npx remotion render <CompositionID> <出力ファイル名>

実行例:

npx remotion render HelloWorld out.mp4

正式な構文

より明示的に指定する場合は、以下の正式構文を使用します：

npx remotion render <エントリーファイル> <CompositionID> <出力ファイル名>

実行例:

npx remotion render src/index.tsx HelloWorld out.mp4
Mac (Apple Silicon) ユーザーへ:
M1 / M2 / M3 チップ搭載のMacでは、書き出し時に画面が黒くなることがあります。
その場合は --gl=angle オプションを付けてください。
npx remotion render HelloWorld out.mp4 --gl=angle

また、Homebrew経由でFFmpegをインストールしておくとトラブルが減ります（環境構築セクション参照）。

Web公開 (Bundle)

Remotionで生成したプロジェクトの場合、npm run build を実行すると、動画プレイヤー機能を持ったWebページ一式（WebBundle）が生成されます。 これをGitHub PagesやVercelにデプロイすれば、ブラウザ上で動画を再生できます。

クラウドレンダリングでも使用:
WebBundleは、Remotion LambdaなどのクラウドレンダリングAPI用途でも必要になることがあります。
render と build の違い
render = 動画ファイル（MP4）を書き出す
build = Webページとして再生できる形式を出力する（WebBundle）

パフォーマンス最適化

大規模な動画プロジェクトでは、レンダリング速度やメモリ使用量が問題になることがあります。以下のテクニックを活用しましょう。

OffthreadVideo

動画ファイルを別スレッドでデコードすることで、メインスレッドの負荷を減らせます。

import { OffthreadVideo } from 'remotion';
<OffthreadVideo src={videoSrc} />

prefetch() で読み込み高速化

画像や動画を事前に読み込むことで、レンダリング時のフリーズを防げます。 より確実に行うには、delayRender と組み合わせます。

import { prefetch, delayRender, continueRender } from 'remotion';

const handle = delayRender();

prefetch(staticFile("heavy-image.png"))
  .then(() => continueRender(handle));

その他のTips

  • pauseAnimation: 開発環境でCPU負荷を下げたい場合に使用（本番レンダリングには影響しません）
  • 未使用画像の解放: メモリリーク防止のため、不要な画像は参照を切る
  • フレームレート調整: 60fps → 30fps にするだけで書き出し時間が半減
